# 02 — E-commerce Analytics: sales, repeat purchase and customer cohorts

## Бизнес-вопросы

Как менялись оборот и количество заказов? Какова структура клиентской базы? Как распределяются клиенты по RFM-сегментам и как меняется когортное удержание? Какие страны дают наибольший оборот в историческом наборе?

## Источник и лицензия

UCI Machine Learning Repository, Online Retail II, dataset 502. 1 067 371 строк транзакций британского зарегистрированного интернет-магазина подарочных товаров за период с 01.12.2009 по 09.12.2011. В данных есть пропуски, отмены/возвраты, отрицательные количества и покупатели-оптовики.

Источник: https://archive.ics.uci.edu/dataset/502/online+retail+ii  
Лицензия: Creative Commons Attribution 4.0 International (CC BY 4.0).  
Цитирование: Chen, D. (2012). DOI: 10.24432/C5CG6D.

Исходная книга Excel (~43,5 MB) скачивается из UCI при первом запуске и не коммитится в Git.

## Метод и правила качества данных

- Сохраняются все исходные строки в локальной raw-копии; исходник не перезаписывается.
- Отмены распознаются по префиксу C в InvoiceNo; отрицательные количества рассматриваются как возвраты.
- Для gross-sales KPI учитываются строки с положительным Quantity, неотрицательным Price и корректной датой; нулевые цены сохраняются как бесплатные позиции/образцы, отрицательные цены исключаются. Отмены и возвраты исключаются, но их количество отражается в quality report.
- Строки без Customer ID остаются в продажах и агрегатах по заказам, но исключаются из клиентского RFM/когортного анализа.
- Точные дубликаты подсчитываются, но автоматически не удаляются: без бизнес-контекста одинаковые строки могут быть отдельными строками счёта.
- Нулевые цены сохраняются как допустимые бесплатные позиции/образцы; отрицательные цены исключаются из валовых продаж.
- RFM использует average-rank scoring, чтобы одинаковые значения не получать искусственно разные оценки. При единственном клиенте назначаются нейтральные оценки 3/3/3. Именованные сегменты: Champions, Loyal customers, New customers, Potential loyalists, At risk и Hibernating.
- Когортная матрица дополняется нулевыми наблюдениями для месяцев без повторных заказов, а не оставляет такие месяцы невидимыми.
- Денежные суммы рассчитываются в GBP как Quantity × Price.
- Когорта клиента — месяц первой наблюдаемой покупки; retention — доля клиентов когорты с покупкой в соответствующем месяце.
- Recency считается относительно последней даты внутри датасета + 1 день, а не относительно сегодняшней даты.

## Как запустить

Из корня репозитория:

    pip install -r requirements.txt
    python projects/02_ecommerce_analytics/run.py

Для полной обработки Excel на 1M+ строк понадобится достаточный объём оперативной памяти. Pipeline читает оба листа исходной книги.

## Результаты в outputs

- summary.json и findings.md — рассчитанные KPI и интерпретация результатов;
- sql_reconciliation.json — проверка совпадения SQL- и pandas-агрегатов;
- monthly_sales.csv — выручка, заказы и AOV по месяцам;
- customer_rfm.csv — recency, frequency, monetary и оценки R/F/M;
- rfm_segment_summary.csv — агрегированное количество клиентов и средние показатели по именованным сегментам;
- cohort_retention.csv — размер когорты и retention по месяцам, включая месяцы без повторных заказов;
- country_sales.csv — продажи по странам;
- quality_report.json — размер raw, пропуски, отмены, возвраты, невалидные строки и точные дубликаты;
- clean_sales.csv — очищенные строки продаж, включая строки без Customer ID;
- ecommerce.duckdb — таблицы для SQL;
- dashboard.html — интерактивная визуализация.

## Ограничения

Набор исторический и относится к одному продавцу; его нельзя выдавать за репрезентативный срез текущего рынка или всех e-commerce-компаний. Значение Customer ID отсутствует у части строк, поэтому customer-level показатели рассчитаны только по идентифицируемым клиентам. В датасете нет себестоимости, маркетинговых расходов, источника привлечения или рекламных затрат — маржинальность, CAC и ROAS не рассчитываются. Оптовые клиенты могут влиять на частоту и размер заказов.
