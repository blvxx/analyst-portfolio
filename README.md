# Analyst Portfolio

**Data Analyst / Marketing Analyst | Python · SQL · pandas · DuckDB · Plotly**

Портфолио из трёх воспроизводимых аналитических проектов на открытых реальных данных. Проекты разделены по типу задачи и источника: поведение пользователей сайта, транзакции интернет-магазина и макроэкономические показатели стран СНГ.

> Все выводы должны быть заново рассчитаны из исходных данных при запуске. Числа в примерах не подменяют фактические результаты. Датасеты не хранятся в Git: загрузка выполняется из первоисточников.

## Проекты

| Проект | Бизнес-вопрос | Данные | Основные методы |
|---|---|---|---|
| 01. Marketing Analytics | Какие характеристики сессии связаны с покупкой и где отличаются конверсии? | UCI Online Shoppers Purchasing Intention, 12 330 реальных сессий | очистка, conversion rate, сегментация, χ², Cramér's V, SQL |
| 02. E-commerce Analytics | Как меняются продажи, клиентская база, повторные покупки и когорты? | UCI Online Retail II, 1 067 371 строк транзакций | ETL, data quality, RFM, когортный анализ, SQL/DuckDB |
| 03. CIS Macro Analytics | Как менялись цифровое развитие и экономические показатели стран СНГ? | World Bank Indicators API, временные ряды по странам и годам | API ingestion, обработка пропусков, сравнение трендов, корреляции |

## Быстрый старт

Требуется Python 3.11+.

1. Создать виртуальное окружение и установить зависимости:

    python -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt

   На Windows PowerShell: .venv\Scripts\Activate.ps1

2. Запустить интересующий проект:

    python projects/01_marketing_analytics/run.py
    python projects/02_ecommerce_analytics/run.py
    python projects/03_cis_macro_analytics/run.py

3. Запустить проверки:

    pytest -q

Каждый pipeline загружает источник, сохраняет неизменённую копию в локальном каталоге data/raw, формирует очищенные таблицы, CSV-отчёты, DuckDB-файл и интерактивный HTML-дашборд в каталоге outputs соответствующего проекта. Каталоги data и outputs не коммитятся.

## Методологические принципы

- Сохранять исходные данные отдельно и не перезаписывать их очищенной версией.
- Не удалять выбросы автоматически: сначала измерить, описать и объяснить решение.
- Не заполнять пропуски без методологического основания. В макроданных пропуски сохраняются и показываются в отчёте.
- Разделять наблюдаемую ассоциацию и причинно-следственную связь.
- Для транзакций отдельно учитывать отмены и возвраты; не считать их обычными продажами.
- Для когорт использовать уникальных клиентов и явно определённую дату первой покупки.
- Не публиковать персональные данные. В этих проектах используются обезличенные исследовательские данные и агрегированные публичные показатели.

## Ограничения портфолио

Это самостоятельные аналитические кейсы на открытых данных, а не коммерческие проекты и не результаты для реальных заказчиков. Датасет онлайн-магазина исторический (2009–2011), поэтому он подходит для демонстрации методов, но не для выводов о современном e-commerce. Данные о веб-сессиях опубликованы в исследовательских целях и не содержат рекламных расходов, поэтому ROAS, CAC и инкрементальный эффект каналов рассчитать нельзя. World Bank API обновляется и может пересматривать исторические значения; время выгрузки фиксируется в metadata.

## Текущий статус

Репозиторий содержит воспроизводимый код, тесты, SQL-запросы, Dockerfile и CI. HTML-дашборды создаются после загрузки данных; публичные хостинговые ссылки на них появятся только после отдельного деплоя. Реальные численные выводы не зафиксированы до запуска pipeline на первоисточниках.

## Публикация интерактивных дашбордов

Дашборды генерируются из свежей выгрузки источников и могут быть опубликованы на GitHub Pages:

1. В Settings → Pages установить Build and deployment → Source: GitHub Actions.
2. Открыть Actions → build-and-deploy-dashboards → Run workflow.
3. Workflow повторно загрузит открытые источники, соберёт три HTML-дашборда и развернёт статический сайт.

До первого успешного запуска workflow публичная ссылка на dashboard site не считается опубликованной. Сами исходные данные не попадают в Pages artifact — публикуются только агрегированные HTML-визуализации.
